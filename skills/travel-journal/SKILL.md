# 旅行路书 · 一个仓库一趟旅行

每个旅行是自己的仓库和 GitHub Pages 站点，保留暖纸色、深绿的摄影杂志风。访客页面只呈现旅行所需信息；研究和技术说明放在 `docs/` 或 `work/`。

## 定位与范围

先读仓库的 `AGENTS.md`、`README.md` 与 [制作流程](../../docs/add-a-trip.md)。本技能的维护副本位于仓库 `skills/travel-journal/`，解析 `SKILL.md` 的真实文件路径后，上两级是仓库根；本地技能入口可能是指向此目录的符号链接。

检查当前 Git 状态和实际源文件，保留无关改动。用户可能从零规划，也可能提供已经制作好的 HTML；按本次需求处理，不把别的旅行的日期、天数、酒店或费用复制成新事实。

## 执行分工

协调者（主模型）负责需求与路线分析、计划、设计决策和独立最终验收；执行委派给用户指定的 Sonnet 5.5 子代理，推理强度 high，分派时写明目标文件、预期行为与验收证据。执行者自报不能替代协调者验收，发布遵守当前授权。细则见 [流程的执行分工](../../docs/add-a-trip.md#执行分工)。

## 执行

1. 从本次描述提取目的地、出发地、日期窗口、完整天数/晚数、人数、交通、预算与拍摄重点。缺少会改变路线的事实时只询问必要信息；其他可独立工作继续推进。
2. 新旅行：`gh repo create <name> --template real-jacket/trip-template --public --clone`（仅在用户本次授权创建远程仓库时执行；否则在本地复制模板目录，目录名即站点路径）。已有旅行仓库直接继续。
3. 新计划按 [需求与来源模板](../../templates/trip-brief.md) 研究（复制到 `work/brief.md`）；已有路书先核本地依赖与原作出处。小红书、抖音、B站调研使用 agent-reach 技能（先跑 `agent-reach doctor --json`），按 [调研手册](references/research.md) 执行；原始资料放 `work/research/`，并与文旅、景区、气象、运营方和吃住资料交叉核对。无法完整读取时保留具体边界，不伪造已观看或精确机位。
4. 制作 `site/index.html`，保留运行必需的相对资产与照片署名；加入桌面、手机都可见、指向 `https://real-jacket.github.io/travel-journal/` 的“回旅行首页”链接。不要复制私有地图配置、平台临时签名或整个研究目录。
5. 填写 `site/trip.json` 与 `site/cover.webp`（扩展名与实际格式一致；署名必填，本人照片的 `imageSource` 可为空）。
6. 地图：编辑 `map.json`，用 `pnpm map:build --routes|--extract [--dry-run]|--landcover|--validate` 生成 `site/map/`，页面里把 `MAP_READY` 改为 `true`。
7. 执行 `pnpm check`；自己运行 `pnpm preview`，用真实浏览器核对 1280px 桌面与 390px 手机：地图渲染、控制台无错误、无横向溢出、返回首页链接、本次核心交互。测试通过不能替代运行和视觉证据。
8. 若本次用户已要求上传或上线：按授权提交并推送，启用 Pages（Actions 源），等待该 commit 的工作流成功，打开公网站点与 `trip.json` 验证；再向旅行首页仓库提 PR，把站点网址加入其 `trips.json`。仅要求草稿或本地制作时，交付该范围的实际结果。

## 旅行内容标准

- 拍摄参考选择能学习构图的本人作品，明确地点、地面/平台/岸边/航拍视角和可进入方式。原作拍摄日、发布日期、原 EXIF 与本路书参数建议分开；成片后期、叶色与雾的未知情况标清。署名和原帖不是自动转载授权。
- 地图用共用 `TripMap` 模块和 `pnpm map:build` 生成的数据：土地覆盖着色（森林/植被/农田/城镇/水体）加山体阴影、分级路网（高速/国省道/县道/乡道，含编号）与行政境界地名、按天的真实道路路线和中文图例；国界与争议线不画。地图下方保留按段的“用高德查看路线”清单（起点 → 途经 → 终点，GCJ-02，驾车模式）；详细机位信息放在侧栏。真实道路轨迹与方向示意分别标清，停车入口与景区参考中心不能混用。
- 日程给交通、吃饭、睡眠和停拍留时间；电车旅行使用本次实测续航与电池信息安排补能。住宿逐晚匹配下一处机位；历史设施/消费与当前可用性/预算分开。
- 候选计划用 `planned`；历史路书用 `archived`，不因日期已过声称旅行实际完成。

## 交付

说明新增或更新了什么、可用入口、检查证据，以及当天现场信息、网络依赖或图像许可的具体未核实项。标准流程不授予未来任意旅行的发布权限，也不新增后台、账号或数据库。
