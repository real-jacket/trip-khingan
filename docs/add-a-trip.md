# 制作一份旅行路书

每个旅行是一个独立仓库和一个独立的 GitHub Pages 站点，由本模板创建；“旅行首页”（`travel-journal`）只是入口，通过各旅行的 `trip.json` 读取卡片信息。以下路径均相对本仓库根目录；研究草稿留在被 Git 忽略的 `work/`，访客只看到旅行内容。

## 执行分工

协调者负责需求与路线、设计决策、计划与任务拆解，以及独立最终验收。协调者同时负责分析与审核；实际执行交给用户指定的 Sonnet 5.5 子代理（high effort），分派时明确目标文件、预期行为与验收证据。执行者提交实际产物和检查结果，不能以自报成功代替协调者验收。发布仍遵守用户当前授权。

## 1. 从模板创建仓库

```sh
gh repo create <name> --template real-jacket/trip-template --public --clone
cd <name>
```

`<name>` 就是站点路径：`https://real-jacket.github.io/<name>/`。仓库目录名需与之相同，本地预览才会用同一子路径。不要在没有用户本次授权时创建或推送远程仓库。

## 2. 把旅行需求说清楚

确认出发地、可用天数、日期窗口、同行人数、驾驶方式、摄影题材和预算。电车填写实测高速续航、电池电量与补能习惯；时间尚未确定时保留候选日期。

按 [需求模板](../templates/trip-brief.md) 填写（复制到 `work/brief.md`），也可直接把需求交给 Claude Code 或 Codex。不要沿用别的旅行的天数、路线、酒店或预算。

一份可执行路书至少包含：

- 每天的路线、驾驶预算、吃饭、休息和住宿；往返交通也计入天数。
- 经典拍摄地点与专业成片、停车与步行入口、建议光线窗口、构图和设备建议。
- 一张整合地形、水体、城市/乡镇、道路与每天路线的地图。
- 沿途餐饮、逐晚住宿、补能节奏、费用口径和出发前复核事项。

## 3. 研究并留下可追溯资料

小红书、抖音、B站调研走 agent-reach，查法、降级、落盘与台账规则全部在 [调研手册](../skills/travel-journal/references/research.md)：开工先跑 `agent-reach doctor --json`，原始资料放 `work/research/`，台账用 [brief 模板](../templates/trip-brief.md) 的“来源台账”表，链接用规范化形式（不含 `xsec_token`）。再与当地文旅、景区、气象、道路/充电运营方、酒店和餐厅资料交叉核对。公开路书只呈现读者需要的署名、出处与必要不确定性。

- 日期没有证据就写“未标”；发布日、拍摄日、生效日分开。旧实拍不代表当季叶量，旧酒店设施不代表当天有房或可充电。
- 搜索摘要、封面与完整原图分别标清；不声称看过未实际观看的视频。

### 选择可以参考拍摄的经典成片

- 优先作者本人风光或旅拍作品，有明确地点、完整画面和原作入口；不凭名称断言职业资格。
- 选择能读出前景、中景、远景、光线、尺度和画面组织的作品。作者指定图序时逐张对应地点；地面、观景台、岸边、游船和航拍视角分开，不把航拍图当作地面可复刻机位。
- 图旁写作者、原帖、地点、拍摄日/发布日期、建议到位时间和复现技巧。原作未给 EXIF 时，建议参数明确为本路书分析。
- 后期处理过的树色、水面、天空等说明为成片参考，不据此保证现场条件。
- 发布副本保留署名。本人照片注明本人摄影；第三方图片核对许可或作者授权，来源链接本身不构成转载许可。

### 地图和机位

每份路书一张整合地图：地形、水体、城镇、分级道路和按天切换的真实道路路线（不用直线示意冒充驾车路线）。方案是 MapLibre + 同源 PMTiles 底图 + 地形，路线制作时用 OSRM 生成，导航走高德深链，依据见 [地图选型](map-selection.md)。共用模块在 `site/vendor/map/`（本仓库自带，不依赖别的站点）。

编辑根目录 `map.json`（bbox、分层抽取范围、路线途经点；坐标均为 WGS-84），然后：

```sh
pnpm map:build --routes             # OSRM 生成 site/map/routes.geojson（≤1 请求/秒，非商用）
pnpm map:build --extract --dry-run  # 先看底图/地形体积
pnpm map:build --extract            # 生成 base.pmtiles 与 terrain.pmtiles（需要 pmtiles CLI）
pnpm map:build --landcover          # 由 ESA WorldCover 生成 landcover.pmtiles（需要 uv）
pnpm map:build --validate           # 复用旧路线时，只检查回头路
```

低缩放层用大范围、高缩放层只覆盖路线走廊和点位；页面 `maxBounds` 不超出已制作范围。`site/map/` 合计不超过 40 MB（测试强制）；重生成的二进制会永久留在 Git 历史里，定稿后别反复重建。

底图是土地覆盖地形图：森林、灌草、农田、城镇、水体/湿地、裸地用不同颜色区分，上面叠浅山体阴影，再叠分级道路（含 G/S 编号）和省/市/县界与地名；国界与争议线不画。页面用 `TripMap.renderLegend` 放中文图例。

地图下方保留“用高德查看路线”分段清单：按当前方案/天把相邻点位切成“起点 → 途经 → 终点”段，用 `TripMap.navSegments` 与 `TripMap.amapRoute` 生成高德驾车导航链接（坐标转 GCJ-02）。画出的路线用来看，分段导航用来走，两者都要有。

模板页面中 `MAP_READY` 为 `false` 时只显示“地图制作中”说明，不请求地图数据；生成 `site/map/` 后改为 `true`。点击地图点位只定位并更新侧栏；技术接口、坐标转换和密钥说明不写进访客页面。

### 自驾、补能、吃住与费用

驾驶时间加上快充、排队、午饭、会车、停车、步行与休息；不要用自由流车程填满拍摄日。电车用本次车型和相近温度/车速下实测续航，记录起步电量、最低到站电量、公共站及备选、住宿充电条件；存在桩不等于可用。费用写清一车几人、房间数、餐费口径、电价和里程余量，历史消费与当前预算分开。住宿逐晚匹配第二天机位；营业、菜单及房量按临近行程再查。

## 4. 制作站点

所有发布内容在 `site/`，Pages 原样发布该目录：

1. 替换 `site/index.html` 的占位内容；只放运行必需的本地图像、脚本和样式，一律用相对路径（站点位于 `/<name>/` 下，不用以 `/` 开头的路径，也不引用 `site/` 之外）。
2. 保留桌面与手机均可见的“回旅行首页”链接，指向 `https://real-jacket.github.io/travel-journal/`；保留照片署名与原有交互。
3. 封面放 `site/cover.webp`（扩展名必须符合实际格式）。
4. 填写 `site/trip.json`，旅行首页读取它：

| 字段 | 填写规则 |
|---|---|
| `id` | 小写字母、数字、连字符，建议与仓库名一致 |
| `title`、`subtitle`、`region` | 真实旅行名、简短表达、目的地片区 |
| `status`、`statusLabel` | `planned` / “计划中”或`archived` / “历史路书”；日期已过不等于旅行完成 |
| `date`、`dateNote`、`duration` | 日期以四位年份开头，如`2027.03.12 — 03.15`；明确候选/已定口径及完整天数与晚数 |
| `transport`、`route`、`description`、`tags` | 出发/驾驶方式、至少两个地点的非空字符串数组、概述、至少一个题材的非空字符串数组 |
| `image`、`imageAlt`、`imageCredit`、`imageSource` | 相对 `trip.json` 的封面路径（`cover.webp`）、图像描述、必填署名、原作链接；`imageSource` 可为空字符串表示本人照片 |
| `highlights` | 路书实际具备的内容，如每日路线、机位、吃住和补能 |

## 5. 检查与验收

```sh
pnpm check
pnpm preview            # http://127.0.0.1:4190/<name>/，支持 Range，与 Pages 同一子路径
```

`check` 运行零依赖测试：清单契约、相对资源、公开文件安全、地图数据与体积、高德分段、Markdown 链接。测试通过不是地图或视觉验证。

- 在真实浏览器按 1280px 桌面与 390px 手机检查：标题、图片、控件可读，无横向溢出，无控制台错误，“回旅行首页”可见可点。
- 地图渲染出土地覆盖、分级道路、境界与地名、按天路线和图例；高德分段链接数量与方案/天一致。
- 照片加载、放大/关闭、日期/行程选择、地图缩放与按天路线、点位侧栏、已有清单等核心交互实际可用。
- 公开文件不含私有地图配置、平台临时签名、token、`/Users/`或本地服务路径。对无证据事项保留明确边界。

第三方地图/平台链接受网络影响；出发前仍要复核路况、物候、住处和桩况。

## 6. 发布并加入旅行首页

仅当用户本次明确要求上传或上线时执行，授权范围以本次请求为准。

1. 提交并推送 `main`；在仓库 Settings → Pages 把 Source 设为 GitHub Actions，等待对应 commit 的工作流完成。
2. 打开 `https://real-jacket.github.io/<name>/` 与 `.../trip.json`，核对图片、地图（PMTiles Range 请求返回 206）与返回首页链接。
3. 向旅行首页仓库（`travel-journal`）提 PR，把本站网址加入其 `trips.json`；首页读取 `<站点网址>trip.json`。首页主推第一个 `planned` 项。

部署成功与网站可用分别确认；返回仓库、网站 URL 和验证边界。本流程不为未来任意旅行提供空白发布授权。
